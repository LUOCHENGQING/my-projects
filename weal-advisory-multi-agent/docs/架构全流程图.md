# 财富管理投顾多智能体 · 全流程架构图

> 本文件由项目代码反向核对后手工整理：节点名、连边、规则条数、状态枚举均取自
> `src/pipeline.py`、`src/engine/langgraph_engine.py`、`src/engine/native.py`、
> `src/suitability/rules.py`，与代码一致。

![架构全景图](架构全景图.png)

## 一句话定位

**约束驱动（constraint-driven）**：先把客户硬约束求解成可行域，再让 Agent 在可行域内
做多目标权衡与解释。确定性的部分（约束校验、适当性判定、压力测试、版本快照）**绝不交给模型**。

```mermaid

    P["① 画像与约束提取　profile 节点 → ClientProfilingAgent<br/>读 clients.json / questionnaire.json，提取硬约束<br/>（风险等级 · 投资期限 · 流动性下限 · 集中度上限）"]
    S["② 候选池筛选（确定性）　screen 节点 → ProductScreeningAgent<br/>constraints.screen_products()：逐个剔除不可投产品并留原因码（16 类）"]
    O["③ 组合求解（可行域内）　optimize 节点 → PortfolioOptimizerAgent<br/>optimizer.build_portfolio() 多目标打分 + 确定性修复循环<br/>不变量：被接受的组合，约束违反数恒为 0"]
    G{"④ 适当性硬闸门（确定性纯函数）<br/>suitability 节点 → SuitabilityOfficerAgent<br/>22 条规则 = 15 block + 7 warn<br/>S-FEASIBLE-POOL = veto（可行域为空直接拒）"}
    H["⑤ 人工确认闸门（在建议书定稿之前）　human_gate 节点<br/>触发：规则豁免 / 内控集中度预警线 / 高龄客户<br/>--auto 自动放行；非交互环境必须降级留痕"]

    OUT(["输出：投顾建议书 + 反事实 + 压力测试 + 风险揭示 + 双录留痕<br/>状态 final / final_degraded / final_after_escalation"])

    REJ(["blocked：直接拒绝（veto）"])
    ESC["escalate 节点：轮次用尽仍 block，升级人工"]
    REJH(["rejected_by_human：人工否决"])
    VC["版本链：v1 blocked → v2 final → v3 final<br/>每版均为 SHA-256 不可变快照"]

    P --> S --> O --> G
    G -->|"block 命中 → 打回重配<br/>TightenSpec 单调收紧（最多 2 轮）"| O

    G -->|"轮次用尽"| ESC
```

## 状态机（同上流程的等价表述）

```mermaid
stateDiagram-v2
    [*] --> profile
    profile --> screen
    screen --> optimize
    optimize --> suitability
    suitability --> optimize: block 命中 → 收紧约束重配（最多 2 轮）
    suitability --> human_gate: pass
    suitability --> escalate: 轮次用尽 / veto 之外的不可修复项
    escalate --> human_gate: 转人工（保留失败原因）
    human_gate --> narrative: 通过 / 自动放行 / 降级留痕
    human_gate --> [*]: 人工否决（rejected_by_human）
    narrative --> [*]: 建议书 + 反事实 + 压力测试 + 版本落盘
```

## 三条关键设计约束

| 约束 | 代码位置 | 说明 |
| --- | --- | --- |
| 可行域单调收紧 | `src/constraints.py` `TightenSpec` | 打回重配只会让约束更严，因此多轮必然收敛，不会来回震荡 |
| 被接受的组合违反数恒为 0 | `src/optimizer.py` `build_portfolio` | 结构性保证（修复循环兜底 + 现金缓冲），不是概率事件 |
| 人工确认在定稿之前 | `src/pipeline.py` `node_human_gate` | 未确认/被否决时不会产出正常定稿，流程上锁死 |

## 双引擎一致性

`src/engine/langgraph_engine.py`（默认）与 `src/engine/native.py`（零依赖降级，`MAX_STEPS=64`）
**共用同一批节点函数与同一套路由判定**（`AdvisoryPipeline.route_after_suitability`），
连边顺序一致：`suitability --pass--> human_gate --> narrative --> END`，
`--reject--> escalate --> human_gate --> narrative --> END`。
